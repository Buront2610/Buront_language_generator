## Classification and its limits

Categories remain preservation/layout-only, ending-only, lexical-only, fixed-phrase construction, structural-fixed-form-only, source-body composition and invalid structural program. Body composition needs a separately rerun bounded source proof, exact slot coverage and provenance, at least two non-context relation roles, changed block text and either actual role-order inversion or changed source-sentence grouping. A `STRUCTURAL` label, phrase wrapper, nominalized ending or marker/context shuffle alone does not qualify.

Copied-piece inversion, all source-bound-piece inversion, relation-role inversion and split/fusion are separate fields. Split/fusion compares original GiNZA sentence spans to terminal-delimited output groups; it is a finite surface diagnostic, not an independent syntactic judgment. The verifier rebinds plans from original IR but shares recognizer/grammar code with the generator. It is not an independent general semantic oracle. Earlier action/scope failures passed those bounded checks, which is why their raw evidence and retrospective reviews are preserved.

The pre-B2 classifier audit tightened direct coverage/provenance/order requirements; it did not change any B1 body/movement/grouping counts. Original classification definitions have not been relabeled to turn this final prospective failure into success. Human S/Q stays null throughout.

## Reproduction

Use Node24 and the pinned Python environment, and set BURONT_PYTHON when needed. The commands reconstruct isolated engines; they do not build the current checkout or substitute its later code. Public reruns of all suites are regression/reproduction, never a new prospective claim.

```sh
REPO="$PWD"
PKG="$REPO/artifacts/typed-rhetorical-generation-20261006"
BASE=$(mktemp -d)
AFTER=$(mktemp -d)
RUN=$(mktemp -d)
export BURONT_PYTHON="$REPO/.venv/bin/python"
git archive a25c40a82c80dd9f8209aecf21b669ede8d5619a | tar -x -C "$BASE"
git archive a25c40a82c80dd9f8209aecf21b669ede8d5619a | tar -x -C "$AFTER"
gzip -dc "$PKG/final-core.patch.gz" > "$RUN/core.patch"
gzip -dc "$PKG/final-validation.patch.gz" > "$RUN/validation.patch"
git -C "$AFTER" apply "$RUN/core.patch"
git -C "$AFTER" apply "$RUN/validation.patch"
ln -s "$REPO/node_modules" "$BASE/node_modules"
ln -s "$REPO/node_modules" "$AFTER/node_modules"
(cd "$BASE" && npm run build:engine)
(cd "$AFTER" && npm run build:engine)
node "$PKG/scripts/recreate-composition-evaluation-assets.cjs" --baseline-root "$BASE" --out "$RUN/assets.json"
# Verify assets SHA256 and AFTER/build-info.json.sourceHash against the values above.
for SUITE in regression prospective; do
  INPUT="$PKG/$SUITE-cases.json"
  if [ "$SUITE" = prospective ]; then INPUT="$PKG/prospective-input.json"; fi
  node "$PKG/scripts/evaluate-typed-rhetorical-generation.cjs" --engine-root "$BASE" --assets "$RUN/assets.json" --cases "$INPUT" --out "$RUN/before-$SUITE.json.gz" --revision a25c40a82c80dd9f8209aecf21b669ede8d5619a
  node "$PKG/scripts/evaluate-typed-rhetorical-generation.cjs" --engine-root "$AFTER" --assets "$RUN/assets.json" --cases "$INPUT" --out "$RUN/after-$SUITE.json.gz" --revision sourceHash:66c681f3d2f48ff6bb7d218711da08be4ea948c06d6d5a861d83b2364e491092
  node "$PKG/scripts/compare-typed-rhetorical-generation.cjs" --before "$RUN/before-$SUITE.json.gz" --after "$RUN/after-$SUITE.json.gz" --before-root "$BASE" --after-root "$AFTER" --out "$RUN/full-$SUITE.json.gz" --summary "$RUN/$SUITE-summary.json"
  node "$PKG/scripts/compact-typed-rhetorical-evaluation.cjs" "$RUN/full-$SUITE.json.gz" "$RUN/$SUITE-comparison.json.gz"
done
node "$PKG/scripts/verify-typed-rhetorical-evaluation.cjs" "$PKG"
```

To rerun the reconstructed validation suite: `(cd "$AFTER" && npm run typecheck && npm test && npm run build:assets && npm run diagnose)`. For serialized HTTP checks, stop competing CPU-heavy work and run `node "$AFTER/scripts/benchmark-structural-generation.cjs" --root "$AFTER" --output "$RUN/near-limit-api.json"`.

The raw recorder intentionally inherits `replayManifest.engineVersion` from frozen historical assets; that value is not actual final-code identity. Use source/module inventories, `engineHash` and `buildInfo.sourceHash`. Likewise, an archived `buildInfo.toolCommit` can be historical; archive revision plus rebuilt module hashes establishes provenance. Production API validation uses freshly rebuilt assets and verifies actual final-engine identity separately.

For historical development reproduction, substitute that directory's core/validation patches and use its exact input/summary. Its old compact evidence and original tests must not be evaluated as though they came from current code.

Large repeated development reports and the independent safety JSONL are stored as `.json.gz` / `.jsonl.gz`; `additional-evidence-compression.json` verifies their exact decompressed bytes. The readable Markdown reports and full compact comparisons remain alongside them.

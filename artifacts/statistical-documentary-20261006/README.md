# 実在原作・改変文による統計生成の小規模実験

## 結論

**公開された人の原作と改変を実際に照合し、65区間対で fast_align＋Moses＋KenLM を学習・実行しました。候補を作る経路は動きましたが、意味保持やブロント語としての品質改善は実証していません。**

最初にリポジトリ内だけを調べて「人手対訳0件」とした監査は、Web上の原作・改変が存在しないという意味ではありませんでした。今回の作業では、LLMで通常文を創作せず、既存の公開文字列を出典・位置・ハッシュ付きで取り出しています。手入力のExcelを埋めることは、この資料ベースの研究を進める前提ではありません。

本番エンジンは変更していません。マージ・デプロイ・モデル切替もありません。公開操作は一度キャンセルされて停止しました。その後、コード・出典メタデータ・集計・短い出力例の公開について改めて許可を得ています。改変全文・学習本文・モデル重みは公開しません。

実際の変更ファイル・関数・スキーマ・ライブラリ呼出し順は [日本語の実装詳細](../../docs/statistical-generation-implementation-20261006.md) を参照してください。

## 見つかった原作との対応

- [謎の改変物](https://kenkyonanight.xxxxxxxx.jp/oii.html)：『蜘蛛の糸』『雨ニモマケズ』『猿かに合戦』などの実在原作と対応。原作者・版・区間を記録し、単に題名が似た別作品には結び付けていません
- [注文のおおすぐる料理店](https://kenkyonanight.xxxxxxxx.jp/suguru.html)：宮沢賢治の[青空文庫本文](https://www.aozora.gr.jp/cards/000081/files/43754_17659.html)と対応。金額・時間・視点の変更を含むため、意味同値の正解データとは扱いません
- [ハーメルンの改変作品](https://syosetu.org/novel/107412/)：『寺生まれのTさん』の「赤いワンピース」「夜釣り」「悪夢」など6原話を既存記録まで追跡。参照したまとめは二次転記で、厳密に同じ版を使ったかは未確定です
- 『時そば』は具体的な既存本文まで照合しています

全17文書・12原作ファミリーのURL、取得版、出典ハッシュ、著作者情報、権利状態は `source-catalog.json` にあります。公開・人による執筆の根拠と、意味同値の人手審査は別です。作者・版の不確かさを消していません。

## 学習・分割

- 原作／改変の対応窓140組を確認
- 長い窓を、句読点・引用境界と単調な文字列類似度の対応付けで分け、220区間対を作成。文章自体は書き換えず、元文書の連続範囲を参照
- 原作・派生版・重複をまとめて、train/dev/testを9/1/2作品に固定。区間数は146/9/65
- 学習側146区間のうち、保護値の文字列対応が合う65対を使用。81対は保護値不一致で除外。表記差を過剰に拒否する場合もあり、81対すべてが意味破壊だという人手判断ではありません
- 真正な upstream fast_align、Moses抽出・重み付け・デコーダー、KenLMを実行。重みは未調整、語順変更幅0、最大30候補
- 学習済みフレーズ対9,587。LMは実際に使用した学習側の改変本文だけで作成
- LightGBM、KNP、Pyniniは追加していません

派生元を共有する文章は学習とテストにまたがりません。モデルは保留65ケースの原作本文で比較しましたが、これは文学・コピペ由来の領域であり、日常文全般への性能ではありません。65ケースには64種類の入力文字列が含まれます。

## 同じ保留ケースでの実測

基準はmain `4d918a56`、設定は `rewrite / faithful / blend / intensity=2 / series=all` です。

- 基準版：36/65ケースで候補、プール・表示とも計47候補
- 統計生成：計1,480候補
- 入力と基準版のプールにない文字列：ケースごとの合計1,454件、64/65ケースに出現
- 強制除外の診断に当たらない新しい候補があるのは42/65ケース
- 201候補は診断で除外、1,279候補は引き続き人手確認が必要
- 人間による意味保持・文体の評定は0件。「良い変換率」「品質改善率」は未測定

1,454は全ケースを横断したユニークな文の数ではありません。新しい文字列や診断に引っかからないことを、安全性・自然さ・ブロント語らしさの証拠にはしていません。

## 短い実出力

以下はすべて[『注文の多い料理店』の原文](https://www.aozora.gr.jp/cards/000081/files/43754_17659.html)を入力した、実際のデコーダー1位です。良例だけを選んだ評価集合でも、人間の採点結果でもありません。

- `と書いてありました。` → `と書いてＰＯＰしていた`
- `犬がふうとうなって戻ってきました。` → `犬がふうとうなって戻って札していた`
- `WILDCAT HOUSE` → `WILDCAT HOUSE`

「札していた」のような接続や、文中への語の付加が実出力に現れています。最後の例はコピーのみです。対応する基準版の実出力とOOV率は `short-examples.json` を参照してください。候補数だけで成功とは言えません。

## 修正した比較の誤りと、事後の診断追加

初回の比較アダプターは未対応の `invent` を指定し、基準版を65件すべて実行拒否にしていました。その「基準0件」は比較として無効です。独立レビューで発見し、UIで対応している `blend` に修正。未対応モードの返却を実験エラーにするテストを追加し、同じ65ケースの比較・ブラインド確認ファイルを全て再生成しました。

また、全文が保護対象の引用だけなのに、その外側へ語を足す候補を検出しました。入力に編集可能な本文がない場合の付加を強制除外する診断を、結果を見た後に追加しています。これによる197候補の追加除外は事後修正です。事前凍結した安全性試験とは主張しません。

学習データ、分割、候補文字列・順序・点数はこの修正で変えていません。独立レビューで全1,480候補の一致、学習・アラインメント・ARPA・KenLM・フレーズ出典の一致を確認しました。初回の無効な比較記録はローカルに保存し、最終集計には使っていません。

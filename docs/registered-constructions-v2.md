# 登録済み意味構文による本文変換

## 対応範囲

`packages/core/constructions.ts` は、通常の表記・句読点変換とは別に、入力の意味役割と活用を束縛して本文を書き換える閉じた構文台帳です。自由な新作生成や、原文に無関係な名言の追加ではありません。`intensity >= 2`、本文変換・原文保持モードで利用します。

| 構文 | 入力条件 | 出力例 | 原ログ系列 |
| --- | --- | --- | --- |
| anger-peak v1 | 怒りが/は頂点に達するという明示的な最大程度。普通形/丁寧形、過去/非過去 | 私の怒りは頂点に達しました → 俺の怒りは有頂天になった | night |
| deep-sadness v1 | とても/大変という明示的な高程度の悲しさ。普通形/丁寧形、過去/非過去 | 太郎はとても悲しかった → 太郎は深い悲しみに包まれた | katuru |
| time-expired v1 | すでに/既に/もう + 時間切れという状態。コピュラなし/普通形/丁寧形、過去/非過去 | もう時間切れだった → 時既に時間切れだった | gg |

悲しさの構文は、明示された主語が人称代名詞または解析上の人名で、競合する主題や、にとって・だけが等の別の参与者構造がない場合に限ります。知らせ・死・映画など悲しさの原因を経験者へ変えることはしません。主語省略は補完せず保持します。

原文の主語・所有者は残し、省略されている経験者を補いません。「私→俺」は別の有限語彙変換です。構文の内部にある同じ原文範囲を、語彙変換と意味構文が二重に編集することはありません。

## 保留するもの

- 否定、推測、条件、予定、質問、命令、引用・伝聞、括弧内、不完全な引用
- 「温度が頂点に達した」のように意味領域が異なる入力
- 「少し悲しい」「少し腹を立てた」のように程度を引き上げる必要がある入力
- 「時間切れ」のみの入力への、原文にない「すでに」の追加
- 埋め込み節、未登録の活用、未知の構文。未対応箇所を自由な言い換えで埋めません

これらは意味構文を適用せず、適用条件を満たす通常の表記変換だけを残します。出力候補を3件にするための水増しは行いません。

## 証拠と系列制約

各構文は、台帳内の固定された原ログ文ID・引用部分・系列へ結び付きます。現在は各構文につき1件の原ログ根拠を採用する初期実装です。`series=all` では全3種を利用できますが、特定系列では、その構文が実際に裏付けられる系列だけで利用できます。名言集の見出しや編集者の説明は、意味構文の原ログ証拠として扱いません。

一般的な一人称・語尾規則にも元から個別の出典と厳密な系列フィルタがあります。このため、構文が利用可能な系列でも、別系列の一人称・語尾規則は利用できない場合があります。系列を越えて同じ表現を使うための汎用根拠や、複数用例をまとめた採用条件は、現時点では実装していません。

## 独立照合

`QuotePlan.construction` は、構文ID/バージョン、実現形ID、原文Unicodeコードポイント範囲、スロットの原文範囲・token ID・文字列、事実ID、時制・極性・実現性・完了・帰属・態、出典ID、別途適用した語彙編集を保持します。

`validateConstruction` は、計画の宣言をそのまま信頼せず、原文から以下を再計算します。

1. 採用範囲と原文順の節、各節の事実ID、ノードID
2. 登録構文の適用条件とスロット束縛、実現形
3. 意味構文の固定された原ログ根拠・登録系列、構文ファミリ
4. 有限語彙編集の条件と、全編集から再構成した出力

通常生成とロック再生成の系列判定では、実データ `Assets.evidence` の原ログ種別・系列対応も使用します。`validateConstruction` 単体に渡す本文だけの参照Mapは、語彙出典がどの系列に属するかの証明にはなりません。語彙編集の系列保証は、生成時の絞り込みと `lockedEvidenceCompatible` による実データ照合を含む経路全体の保証です。

`V-construction` と最終段の `S-bounded-construction` は、この限定された検査の成功を示します。一般的な意味同値性、自然さ、文体の良さ、著者本人らしさを保証するものではありません。構文結果は `adaptation` です。入力の名詞が違うだけで `candidate_novel` とは判定しません。

生成中の全候補は内部プールへ保持し、最終照合後に選び直します。APIの公開結果から内部プールは取り除きます。再生成ではロックした節の意味構文・語彙編集も一緒に固定します。変更先の系列に属さない元の出典をロックが含む場合は、実データの系列対応に照らして `LOCK_CONFLICT` とし、出典を新系列へ付け替えません。リプレイでは親計画を再生成してから照合します。

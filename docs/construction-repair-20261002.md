## 今回の実装

1. **命題の範囲を形態素・依存関係で判定**
   `素晴らしい` の `らしい`、`おもしろい` の `もし` を推量・条件と誤認しないようにしました。事実抽出と語尾編集が同じ範囲判定を使います。引用・伝聞・条件・否定の対象を扱い、独立した発言者の節まで一律に変換禁止にしません。
2. **意味を束縛する登録構文**
   怒りの頂点、強い悲しみ、既に時間切れの3系統を追加しました。文字列を普通形へ変換して再入力する方法ではなく、元のUnicode範囲、token ID、人物、活用、程度を保持した単一編集計画を作ります。単なる語尾変化とは別の `CONSTRUCTION` 経路です。
3. **独立照合と再生成契約**
   固定された構文台帳から、適用条件・スロット・実現形・出典・出力を原文に再束縛します。生成器が書いた逆訳や事実IDだけでは通過できません。有限編集、登録構文、一般の変更後再解析を区別し、schema、ロック、replayへ反映しました。
4. **全候補の検証後に最大3件を選択**
   内部プールを最終検証まで保持し、上位案が落ちた場合は残った適格候補を採用します。構文系統、操作の組合せ、変更箇所の表現、全文の順で多様性を比較します。長い共通背景や句読点・一人称の差で多様性を誤判定しないようにしました。seedは適格な同順位候補にだけ作用します。
5. **未対応機能の明示**
   新作・名言作成・自由展開は画面で無効化し、APIは422 `unsupported_generation_mode`、直接エンジンは同じ理由の空結果を返します。語録の応用を新作へ付け替えません。未学習S/Qは `null` のままです。
6. **語録抽出と出典の修復**
   元サイトの実HTMLを再取得し、凡例を除外、インラインタグをまたいだ行を復元、強調を範囲として保存しました。短い見出しも文脈で照合し、曖昧な対応は曖昧として残します。感謝を単一文字「謝」から怒りと分類しません。原ログは変更していません。詳しくは[コーパス由来](quote-corpus-provenance.md)を参照してください。
7. **セットアップ・検査の整合性**
   `npm test` がAPI試験に必要なWebビルドも実行するようにしました。Pythonを呼ぶ試験はOS別パスと `BURONT_PYTHON` に対応しました。READMEの旧Node18/依存不要という記述を現行のNode24/Python3.11へ訂正しました。

## 意図的な制限

- 3系統の閉じた構文の初期実装です。あらゆる同義文を扱う意味解析器ではありません
- 否定・条件・推量・引用・不明な経験者などの危険な変換は保留し、原文を残します
- 構文の自然さや本人らしさの最終評価は未実施です。機械検査通過を人手評価の代わりにしません
- 系列横断の共有構文を自動導入しません。現在は厳密な系列内出典に限定しています。複数用例による汎用的な語尾・一人称の支持拡大は残件です
- LLMによる自由文提案、外部API送信、学習済みS/Q、新作生成、展開型の全面拡張は追加していません

詳細な条件は[登録構文の仕様](registered-constructions-v2.md)を参照してください。

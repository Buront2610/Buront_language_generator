# 「展開を許す」＋「新作候補」が空になる不具合

2026-09-22の利用者報告を受け、現行の生成経路を追跡した。

1. `packages/core/engine.ts` は `makeRewritePlans` だけを呼ぶ。
2. `packages/core/rewrite.ts` は既存の語彙・句・語尾・句読点編集だけを組み合わせ、常に `plan.rewrite` を持つ案を作る。
3. `packages/core/evaluation.ts` の `evaluateNovelty` は `plan.rewrite` のある全案を無条件に `adaptation` にする。
4. 同ファイルの `select` は `invent` で `candidate_novel` だけを通す。したがって、現行経路で `invent` が1案以上を返すことはない。
5. `contextMode === 'full'` を処理するコードは旧 `creation.ts` に残っているが、現行 `engine.ts` から呼ばれない。現行 `rewrite.ts` は `source_order` 固定で、この設定を使わない。

入力に適した案が偶然なかったのではなく、生成機能と画面の選択肢が不整合になっている。既存テストも `invent` の0案を期待しており、生成機能そのものの欠落を検出していなかった。

## 状態

2026-10-02追記: [構文経路の段階修正](construction-repair-20261002.md)で登録構文による応用を追加し、新作・自由展開は明示的な未対応へ変更しました。新作生成そのものが完成したという意味ではありません。以下は2026-09-22時点の調査記録です。

原因特定済み。新作生成機能の修復は未完了。語彙の由来に関する今回の2規則停止とは別件。

起動したHTTP APIでも確認した。同じ原文・強度3・全系列・固定seedで、忠実＋既知表現は内部5案／選択3案、展開＋既知表現も内部5案／選択3案で出力は完全一致。展開＋新作候補は内部5案／選択0案、理由は `no_novel_candidate`。実行結果は `artifacts/lexical-origin-audit-20260922/live-mode-diagnostic.json`。

応用を単に `candidate_novel` に付け替えたり、除外条件を緩めて新作と表示したりしてはいけない。旧生成器は任意の比喩や付け足しが問題となり外されたもので、無検証の再接続も修復にはならない。

必要な修復は、原文の意味・指示対象を保持しつつ構文や論の運びを生成する経路を復旧または実装し、その出力に対して既知表現との比較を行うこと。「展開を許す」による違いと、条件を満たす新作が存在する入力で1案以上を返すことを正例として検査する必要がある。人間による文体評価は利用者が行う。

# PR #3 レビュー指摘の修正（2026-10-02）

対象は `b5c2d962dd60ba9df7ab0b8d1245fa44b4ecf7bf` へのレビューです。提供された本文から再現し、`pr3_review_report.md` / `pr3_review_repro.zip` 自体は取得・閲覧していません。今回の範囲は性能退行、終端句読点、時間切れ構文の再入力だけです。

## 修正

- `permitsRewrite` が編集候補ごとに全文の命題スコープを再構築していた経路を、1回の `makeRewritePlans` 内だけで共有する短命なガードへ変更しました。6案の作成と各編集候補で同じ計算結果を再利用します
- `validateRewrite` は呼ばれるたびに元のIRから独立して1回計算します。生成器の計算結果・プランの申告値を信用するキャッシュ、グローバルキャッシュ、検証の省略はありません。事実抽出・登録構文はそれぞれ従来どおり独立した計算を行います
- 構文の終端は安全な `。` / `！` / `!` の連続と後続空白を許容します。疑問符、引用、条件、推量などに関する既存の形態・依存関係の制限は維持します
- `時間切れ` の同じ述語に結び付く局所的な `時`＋`既に` を検出し、既に実現済みの構文にさらに `時` を付けません。別の節にこの表現があっても、未変換の節は引き続き変換できます

## 検査の設計

`test/v1/rewrite-scope-reuse.test.js` は、保存済みの実解析を明示的に合成反復した1・20・120文で、編集数が増えても全文スコープの計算が生成1回・各独立検証1回のままであることを検査します。計画後に元IRの形態を条件形へ変える改ざん試験では、再検証が新しい形態を読み直して拒否することも確認します。時間による不安定な閾値を回帰テストの合否判定にしません。

構文の試験は実GiNZAを毎回起動する経路と、同じ実サービスから未編集で保存したfixtureの両方を使用します。3系統について `！` / `！！` / `!` / `!!` / 末尾改行を確認し、疑問・引用・条件・推量の対照例を維持します。実際の出力をGiNZAへ再入力する往復、別の節の変換、独立検証で重複した `時` の編集を拒否する試験も含みます。

末尾改行の受け入れは `。\n` / `！！\n` / `!!\n` のように句読点に続く場合です。句読点なしの末尾改行は実GiNZAが空白tokenをROOT、述語をaclへ変更するため、従来の完全な断定文の条件を満たさず保留します。このためだけに構文の対象を広げてはいません。独立検証の重複防止試験は、追加したガードだけを無効にした隔離モジュールで重複編集が生成・検証を通過し、修正版では拒否されることを対照確認しています。

## 性能の測定方法

`scripts/benchmark-rewrite-scopes.js` はレビューされたコミットと修正版の生成処理を分けて測定します。固定された実GiNZA解析の `私は最強だ` を反復し、token ID・係り先・Unicode範囲・文範囲をずらした合成負荷を使います。1200・2400・3000・5000文字の入力を比較し、入力解析、資産準備、生成の時間を混同しません。実際に全文をGiNZAへ渡した解析時間は別項目に記録します。

候補出力のハッシュを比較して、スコープ再利用自体による出力変更がないことを検査します。旧版が測定上限に達したサイズではハッシュ比較を完了したとは扱いません。測定時間は実行環境依存であり、一般的な文体・自然さの品質を示す指標ではありません。

測定結果と最終検査結果は `artifacts/pr3-review-repair-20261002/` に保存します。
